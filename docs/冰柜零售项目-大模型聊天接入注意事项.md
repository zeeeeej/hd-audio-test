# 冰柜零售项目：大模型聊天接入注意事项

## 场景与目标

项目语音交互链路：

> 冰柜麦克风采集语音 → 业务服务器 → Qwen3-ASR 转文字 → DeepSeek 大模型生成回答 → Qwen3-TTS 合成语音 → 业务服务器下发 → 冰柜喇叭播放。

大模型聊天功能的目标是提供一个**了解当前冰柜商品、能连续沟通、回答有依据的导购助手**。本文聚焦 ASR、TTS 之外的大模型接入与业务设计。

## 1. 聊天定位和业务边界

主要面向购买商品的顾客，支持以下场景：

- 购买引导：“怎么买？”“怎么付款？”
- 商品咨询：“有无糖饮料吗？”“哪个便宜？”
- 商品推荐：“推荐一个十块钱以内的。”
- 售后引导：“付款了打不开门怎么办？”
- 简单闲聊：保持自然、简短，适时回到购物需求。

需要明确哪些问题不能直接答应，例如优惠承诺、退款成功、免费开门，避免模型作出业务系统无法兑现的承诺。

## 2. 给模型提供正确的业务信息

模型不知道当前冰柜的实际情况，需要服务器提供或按需查询。

| 信息 | 建议来源 |
|---|---|
| 当前冰柜、门店 | 服务器认证后的设备信息 |
| 商品、价格、库存、活动 | 实时业务接口 |
| 商品配料、营养、规格 | 已核实的商品资料 |
| 购买流程、售后规则 | 维护好的业务知识库 |
| 顾客刚才说过什么 | 当前会话上下文 |

例如顾客问“有没有无糖饮料”，应查询当前冰柜商品及库存后回答；不能因为模型知道某品牌有无糖产品，就说这台冰柜有货。

## 3. 多轮上下文怎么管理

需要支持这样的连续对话：

> 顾客：“有什么无糖饮料？”  
> 助手：“有 A 和 B。”  
> 顾客：“哪个便宜？”  
> 顾客：“那第二个多少钱？”

服务器需要保存当前会话的消息，以及刚才提到的商品、顾客预算等必要信息。同时考虑：

- **会话隔离**：不能把所有使用同一冰柜的人放进一个长期会话。
- **会话结束**：退出、空闲超时后清除上下文。
- **长度限制**：保留近期消息和必要摘要，避免上下文无限增长。
- **数据更新**：历史对话里的价格、库存不能替代当前查询。
- **指代不明**：“这个多少钱”无法确定商品时，应追问。

第一版通常不需要跨顾客的长期记忆。

## 4. 提示词和回答规则

建议把提示词作为可配置、可版本管理的服务端配置，明确：

- 身份：冰柜零售导购助手。
- 风格：口语化、友好、简短，默认一到三句。
- 依据：商品信息以业务查询结果为准。
- 澄清：商品、数量或意图不清楚时，先追问。
- 不确定性：查不到就说明查不到，不编造。
- 播报格式：避免表格、Markdown、长链接。
- 推荐原则：优先满足顾客预算和需求，推荐当前有货商品。

仅靠提示词不能保证正确性，还需要业务接口校验和回答评测。

## 5. 区分“聊天回答”和“执行操作”

“怎么开门”是咨询，“帮我开门”可能是操作，两者需要不同处理。

大模型可以判断意图、提出工具调用请求；服务器负责校验参数、身份和权限，再决定是否执行。DeepSeek 的工具调用流程支持由应用执行工具并回传结果，参见 [DeepSeek 工具调用官方文档](https://api-docs.deepseek.com/guides/tool_calls/)。

特别注意：

- 模型不能自行决定价格、优惠、支付结果。
- 不能依据一句话就认定顾客身份或订单归属。
- 操作失败时不能回答“已经成功”。
- 用户输入、商品描述里的指令不能覆盖服务器权限规则。

如果第一版只做聊天导购，建议仅开放查询类工具。

## 6. 聊天速度与输出控制

语音聊天应重点衡量**用户说完到听见有效回答的时间**。

建议：

- 普通导购优先选择满足准确率要求、响应更快的模型配置。
- 流式生成，按完整短句送入 TTS。
- 限制回答长度、工具调用次数和整轮处理时间。
- 固定购买说明、网络异常提示可用预置话术。
- 支持打断后取消旧回答，避免新问题来了还在播放旧内容。

涉及价格、库存、操作结果的句子，要拿到依据后再播报。

## 7. 故障、安全、成本和效果验证

上线前至少准备以下控制：

| 方面 | 需要考虑 |
|---|---|
| 故障兜底 | 模型超时、限流、业务接口失败时如何回应 |
| 隐私 | 公共设备不继承上一位顾客的订单或个人信息 |
| 密钥 | 模型密钥放服务器，设备不直接持有 |
| 成本 | 上下文长度、回答长度、每轮工具调用、单设备调用频率 |
| 可追踪 | 记录模型版本、提示词版本、调用耗时、工具结果和错误，日志脱敏 |
| 质量评测 | 商品回答准确率、推荐是否有货、连续追问成功率、响应延迟、单轮成本 |

测试问题应来自实际购物场景，尤其覆盖“这个”“刚才那个”等模糊表达、商品同音词、临时缺货、活动过期、连续追问和顾客中途离开。

## 第一版建议范围

**购买引导＋商品查询＋有库存依据的推荐＋售后指引＋短期多轮对话。**

先用真实商品和冰柜环境验证回答正确率、延迟与成本，再加入开门、订单等操作能力。
